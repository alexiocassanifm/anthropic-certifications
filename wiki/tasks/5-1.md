# 5.1 — Manage conversation context to preserve critical information across long interactions

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [5 — Context Management & Reliability](../domains/5-context-management-and-reliability.md) (15%)

## What it tests

What long conversations do to precise facts, and the structural fixes for it.

## Knowledge

**Progressive summarisation is lossy in a specific direction.** It condenses numerical values, percentages, dates, and customer-stated expectations into vague summaries — exactly the facts that matter most.

**The "lost in the middle" effect.** Models process the beginning and end of long inputs reliably but may omit findings from middle sections. This is a design constraint on how you order aggregated input.

**Tool results consume context disproportionately to their relevance.** The guide's example: 40+ fields per order lookup when only 5 are relevant.

**Complete conversation history must be passed in subsequent API requests** to maintain conversational coherence — the API is stateless.

## Skills

- **Extract transactional facts** — amounts, dates, order numbers, statuses — **into a persistent "case facts" block included in each prompt, outside the summarised history.** This is the central technique: facts live in a structured block that summarisation never touches.
- Extract and persist structured issue data (order IDs, amounts, statuses) into a separate context layer for multi-issue sessions.
- **Trim verbose tool outputs to only relevant fields** before they accumulate in context.
- **Place key findings summaries at the beginning of aggregated inputs** and organise detailed results with explicit section headers, to mitigate position effects.
- Require subagents to include metadata — dates, source locations, methodological context — in structured outputs for accurate downstream synthesis.
- Modify upstream agents to return structured data (key facts, citations, relevance scores) instead of verbose content and reasoning chains, when downstream agents have limited context budgets.

## Anti-patterns

- **Relying on summarisation to preserve numbers.** It will not. Extract them structurally.
- **Letting raw tool output accumulate.** Thirty-five irrelevant fields, repeated every turn.
- **Burying key findings in the middle** of a long aggregated input.
- **Passing verbose prose between agents** when the consumer has a limited budget.

## Exam angle

The signature item: *"After several turns, the agent refers to 'the discussed refund amount' instead of the specific figure."* → a persistent case-facts block outside the summarised history.

Watch for distractors that propose *better summarisation prompts*. Summarisation is lossy by nature; the fix is structural extraction, not a better instruction. That is a `prompt-instead-of-enforcement` shape applied to context.

The position-effects item is more distinctive: given a long aggregated input, put the summary first and use explicit section headers.

Distractor families: `solves-different-problem` (improving the summariser), `over-engineered` (a vector store for conversation facts — also touching [out-of-scope](../exam/out-of-scope.md) territory).
