# 1.5 — Apply Agent SDK hooks for tool call interception and data normalization

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [1 — Agentic Architecture & Orchestration](../domains/1-agentic-architecture-and-orchestration.md) (27%)

## What it tests

Hooks as the concrete mechanism behind [1.4](1-4.md)'s guarantees — and the two directions they run in.

## Knowledge

**Two directions, two jobs:**

| Direction | Hook | Job |
|---|---|---|
| **Results coming back** | `PostToolUse` | Transform tool results *before the model processes them* |
| **Calls going out** | Tool call interception | Inspect an outgoing call and block or redirect it |

**`PostToolUse` for normalisation.** Different MCP tools return the same concept in different shapes — Unix timestamps, ISO 8601 strings, numeric status codes. Asking the model to reconcile them on every turn is asking it to do a deterministic transformation probabilistically. Write the transformation.

**Interception for compliance.** A refund above a threshold never reaches the payment system; the hook blocks it and redirects to an alternative workflow such as human escalation.

**The core distinction the guide states:** hooks give **deterministic guarantees**; prompt instructions give **probabilistic compliance**. Choose hooks when business rules require guaranteed compliance.

## Skills

- Implement `PostToolUse` hooks that normalise heterogeneous data formats from different MCP tools before the agent sees them.
- Implement tool call interception hooks that block policy-violating actions (e.g. refunds exceeding $500) and redirect to alternative workflows.
- Choose hooks over prompt-based enforcement when the rule must be guaranteed.

## Anti-patterns

- **Asking the model to normalise formats in the prompt.** It will mostly work. "Mostly" is the problem, and it costs tokens on every turn forever.
- **A prompt rule for a policy limit.** "Never process refunds over $500" is an instruction, not a control.
- **Using a hook where judgment is needed.** The inverse error, and less common but real: hooks enforce what you wrote down. Escalation decisions ([5.2](5-2.md)) and severity classification ([4.1](4-1.md)) need judgment, and a rigid hook will block legitimate cases you did not anticipate.

## Exam angle

Two shapes:

1. *"Backend tools return timestamps in three different formats and the agent misreads them."* → `PostToolUse` normalisation.
2. *"Refunds above policy limits occasionally get processed."* → interception hook that blocks and redirects.

Distractor families: `prompt-instead-of-enforcement`, `over-engineered` (rebuilding the MCP tools to return a common format is more work than one hook, though it is a defensible architecture — watch for "first step" phrasing).

**Know which hook does which.** An item that describes a *result* problem and offers a call-interception fix — or vice versa — is testing exactly that.
