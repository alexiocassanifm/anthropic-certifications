# 3.3 — Apply path-specific rules for conditional convention loading

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [3 — Claude Code Configuration & Workflows](../domains/3-claude-code-configuration-and-workflows.md) (20%)

## What it tests

One decision, cleanly: **conventions that follow file *type* versus conventions that follow file *location*.**

## Knowledge

**`.claude/rules/` files take YAML frontmatter with a `paths` field** containing glob patterns. The rule activates only when Claude works with matching files.

**Path-scoped rules load conditionally** — only when editing matching files — which reduces irrelevant context and token usage.

**Globs beat directory-bound CLAUDE.md** for conventions that span directories. A subdirectory `CLAUDE.md` covers a directory. A glob covers a *pattern* — and test files scattered beside the code they test (`Button.test.tsx` next to `Button.tsx`) are precisely the case a directory-bound file cannot serve.

## Skills

- Create `.claude/rules/` files with YAML frontmatter path scoping — e.g. `paths: ["terraform/**/*"]` — so rules load only when editing matching files.
- Use glob patterns to apply conventions **by file type regardless of directory location** — e.g. `**/*.test.tsx` for all test files.
- Choose path-specific rules over subdirectory CLAUDE.md files when conventions must apply to files spread across the codebase.

## Anti-patterns

- **Consolidating everything into the root CLAUDE.md** and relying on Claude to infer which section applies. The guide's stated objection: it relies on inference rather than explicit matching, which makes it unreliable.
- **A CLAUDE.md in every subdirectory** to cover scattered files. Directory-bound files cannot handle files spread across many directories cleanly.
- **Skills for automatic convention application.** Skills require invocation or a relevance judgment — they contradict the need for *deterministic* application based on file path.

## Exam angle

The canonical stem: *"React components use functional style with hooks, API handlers use async/await, database models use a repository pattern. Test files are spread throughout the codebase alongside the code they test (`Button.test.tsx` next to `Button.tsx`), and all tests should follow the same conventions regardless of location. What's the most maintainable way to ensure Claude automatically applies the correct conventions?"*

Answer: `.claude/rules/` with YAML frontmatter glob patterns.

Know why each distractor fails — the exam tests the *reasoning*, not just the answer:

| Distractor | Why it fails |
|---|---|
| Consolidate in root CLAUDE.md under headers | Relies on inference, not explicit path matching |
| Skills in `.claude/skills/` per code type | Requires invocation or a relevance judgment — not automatic by path |
| A CLAUDE.md per subdirectory | Cannot cleanly handle files spread across many directories |

**The trigger phrase is "spread throughout" or "regardless of location".** When you see it, the answer is globs.

## In production, beyond the guide

Confirmed exactly as described. Extensions the guide does not cover: `~/.claude/rules/` for user-level rules (loaded before project rules, so project rules win), recursive discovery through subdirectories, symlink support for sharing rule sets across projects, and brace expansion (`src/**/*.{ts,tsx}`). Rules *without* a `paths` field load unconditionally at launch with the same priority as `.claude/CLAUDE.md`.
