# 2.5 — Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [2 — Tool Design & MCP Integration](../domains/2-tool-design-and-mcp-integration.md) (18%)

## What it tests

The most mechanical objective on the exam — and therefore among the most reliably scorable. Two facts and one strategy.

## Knowledge

**Grep searches file *contents*.** Function names, error messages, import statements — anything *inside* files.

**Glob matches file *paths*.** Names and extension patterns — `**/*.test.tsx`, `src/**/*.py`.

**Read/Write are whole-file operations. Edit is targeted**, using unique text matching.

**When Edit fails on a non-unique match, fall back to Read + Write.** Edit needs an unambiguous anchor; if the snippet appears more than once, load the whole file and write it back.

## Skills

- Select **Grep** for content search across a codebase — finding all callers of a function, locating an error message.
- Select **Glob** for files matching naming patterns — `**/*.test.tsx`.
- Use **Read then Write** when Edit cannot find unique anchor text.
- **Build codebase understanding incrementally**: start with Grep to find entry points, then Read to follow imports and trace flows — rather than reading all files upfront.
- **Trace function usage across wrapper modules** by first identifying all exported names, then searching for each name across the codebase.

## Anti-patterns

- **Reading everything upfront** to "understand the codebase". This exhausts context and is the wrong answer whenever it appears. Incremental Grep-then-Read is the guide's stated skill.
- **Glob for content, Grep for filenames.** The straightforward inversion.
- **Retrying Edit with a slightly different snippet** when the anchor is genuinely non-unique. Read + Write is the documented fallback.
- **Bash + `grep` shelling out** when the Grep tool exists.

## Exam angle

These items are usually short and factual — a task, four tools, pick one. Ask yourself: *am I looking for something inside files, or for files themselves?*

The one item with depth is the exploration-strategy question, and it always rewards incremental discovery over bulk reading. Distractor family: `over-engineered` / brute force.

The wrapper-module tracing skill is worth memorising as a two-step: **enumerate the exported names first, then search each one.** A single grep for the original function name misses every call that goes through a re-export.
