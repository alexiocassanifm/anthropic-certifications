# 1.2 — Orchestrate multi-agent systems with coordinator-subagent patterns

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [1 — Agentic Architecture & Orchestration](../domains/1-agentic-architecture-and-orchestration.md) (27%)

## What it tests

How you wire several agents together, and — more often on the exam — how you **diagnose** a multi-agent system that is producing a polished, confident, wrong answer.

## Knowledge

**Hub-and-spoke.** The coordinator manages *all* inter-subagent communication. Nothing goes subagent-to-subagent. This looks like unnecessary indirection until you need the three things it buys: **observability** (one place to see what happened), **consistent error handling** (one place that decides what a failure means), and **controlled information flow** (one place that decides who learns what).

**Subagents run with isolated context.** They do not inherit the coordinator's conversation history. This is the foundation of [1.3](1-3.md), and it is the single fact that most multi-agent items hinge on.

**The coordinator's four jobs:** decompose the task, delegate, aggregate results, and decide *which* subagents to invoke based on query complexity. That last one matters — a simple query should not be routed through the whole pipeline.

**Narrow decomposition is a top-level risk.** The guide calls this out specifically: a coordinator that partitions a broad topic too narrowly produces incomplete coverage, and every subagent will look like it is working perfectly. This is the scenario-3 trap.

## Skills

- **Dynamic subagent selection** — analyse the query and invoke only the subagents it needs, rather than always running the full pipeline.
- **Partition scope to minimise duplication** — assign distinct subtopics or distinct source types to each agent, so two agents do not research the same ground.
- **Iterative refinement loops** — the coordinator evaluates the synthesis output for gaps, re-delegates to search and analysis with *targeted* queries, and re-invokes synthesis. It does not accept the first pass as final.
- **Route everything through the coordinator** — for observability, consistent error handling, and controlled information flow.

## Anti-patterns

- **Subagents talking directly to each other.** Always wrong on this exam. It destroys the three properties hub-and-spoke exists to provide.
- **Always running the full pipeline** regardless of query complexity — wasteful, and the guide names dynamic selection as the skill.
- **Accepting the first synthesis** without evaluating coverage.
- **Blaming the agent nearest the symptom.** See below.

## Exam angle

The signature item shape: *"Each subagent completes successfully — the search agent finds relevant articles, the analysis agent summarises correctly, the synthesis agent produces coherent output. However, the final report misses [a third of the topic]."*

**When every component works and the whole is wrong, look at the decomposition.** The coordinator partitioned the task badly and the subagents executed their assignments faithfully. The distractors will blame the search agent's queries, the analysis agent's filters, or the synthesis agent's gap detection — all of which are working correctly *within the scope they were given*.

Distractor families: `blames-wrong-component` (the dominant one here), `solves-different-problem`.

A useful tell: if the stem hands you the coordinator's logs and they show the subtasks, the logs *are* the answer. Read them.
