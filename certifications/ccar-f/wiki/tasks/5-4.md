# 5.4 — Manage context effectively in large codebase exploration

> Task statement title reproduced from *Exam Guide v1.0*. Everything below is this project's own explanation.

**Domain:** [5 — Context Management & Reliability](../domains/5-context-management-and-reliability.md) (15%)

## What it tests

Working on something larger than the context window, and recognising the symptoms when you are losing.

## Knowledge

**Context degradation has a recognisable signature.** In extended sessions the model starts giving inconsistent answers and referring to *"typical patterns"* rather than the specific classes it discovered earlier. That phrasing is the tell: it has lost the specifics and fallen back to priors.

**Scratchpad files persist key findings across context boundaries.**

**Subagent delegation isolates verbose exploration output** while the main agent coordinates high-level understanding.

**Structured state persistence for crash recovery:** each agent exports state to a known location, and the coordinator loads a **manifest** on resume.

## Skills

- Spawn subagents to investigate specific questions — "find all test files", "trace refund flow dependencies" — while the main agent preserves high-level coordination.
- Have agents maintain scratchpad files recording key findings, and reference them for subsequent questions to counteract degradation.
- **Summarise key findings from one exploration phase before spawning sub-agents for the next**, injecting summaries into initial context.
- Design crash recovery using structured agent state exports (manifests) that the coordinator loads on resume and injects into agent prompts.
- Use `/compact` to reduce context usage during extended exploration sessions when context fills with verbose discovery output.

## Anti-patterns

- **Continuing a degraded session** because it still sounds coherent. It will keep answering; it will stop being right.
- **Letting verbose exploration accumulate in the main thread** instead of delegating it.
- **Carrying full history into the next phase** instead of a summary.
- **No crash recovery plan** for long multi-agent runs — everything is lost.

## Exam angle

The diagnostic item: *"Deep into a long exploration session, the agent gives inconsistent answers and references 'typical patterns' rather than the specific classes it found earlier."* → context degradation. The fixes are scratchpads, subagent delegation, summary injection, and `/compact`.

The recovery item: how does a multi-agent exploration survive a crash? → structured state exports plus a manifest the coordinator loads on resume.

Distractor families: `over-engineered` (a database for exploration state when a scratchpad file is the guide's answer), `solves-different-problem` (a bigger model or window — capacity does not fix degradation).

Note the overlap with [3.4](3-4.md) (Explore subagent), [3.2](3-2.md) (`context: fork`), and [2.5](2-5.md) (incremental discovery). They are four expressions of one principle: **keep verbose discovery out of the thread that has to stay coherent.**
