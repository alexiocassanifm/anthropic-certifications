Item 15d4-4.6-003D4 · TS 4.6Scenario 5 — Claude Code for Continuous Integrationselect TWO

You are designing a review architecture for large changes. Which TWO approaches are consistent with the guide’s recommendations? Select TWO.

A Run three passes and report only findings that appear in at least two. Consensus filtering discards intermittently detected bugs — the ones most worth surfacing. Slot C was correct; this was the second pick. suppresses-signal
B Run verification passes in which the model self-reports confidence alongside each finding, to enable calibrated review routing. Finding-level confidence used to route reviewer attention is an endorsed skill, distinct from using self-reported confidence as a proxy for overall case complexity.
C Split large reviews into per-file passes for local issues plus a separate cross-file integration pass. Multi-pass review addresses attention dilution directly, and the integration pass covers what per-file analysis structurally cannot.

Slot B looks like it contradicts the rest of the kit. It does not — the hinge is the word calibrated. tasks/4-6.md names the tension outright: uncalibrated self-reported confidence, used as a proxy for whether a whole case is too hard, is rejected (5.2, 5.5); confidence attached to a specific finding, calibrated against a labelled validation set and used to route reviewer attention, is endorsed (4.6, 5.5). Given a confidence score with no labelled validation set behind it, treat it as the unreliable proxy.
